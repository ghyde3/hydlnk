# Feature map

Where each feature lives in the running product: how to reach it, the selectors the specs drive it with, the code behind it, and the spec that covers it. Selectors are quoted from `tests/e2e/`. Scope and behavior stay in `docs/PLAN.md`; this file is only a lookup.

## Driving the app

- **Start**: `./scripts/init.sh` (Supabase, `.env.local`, db reset + seed, dev server, smoke). Hosts: `localhost:3000` marketing, `app.localhost:3000` app and editor, `<handle>.localhost:3000` tenant. A second checkout sets `HL_DEV_PORT` (read by `playwright.config.ts`, `tests/e2e/helpers.ts`, `scripts/screens.ts`).
- **Run one spec**: `scripts/q.sh pnpm test:e2e <spec path>` (both projects: `phone` 390x844, `desktop` 1440x900). One viewport: add `--project=phone`. Smoke subset: `scripts/q.sh pnpm test:e2e --grep @smoke`. Output goes to tmp/logs; q.sh prints PASS or the failing lines.
- **Screenshots**: `pnpm screens <route> [--host app|<handle>]` writes both viewports to tmp/screens (no sign-in: public and signed-out screens only).
- **URLs in specs**: `url()` from `tests/e2e/helpers.ts`: `url()` marketing, `url("app", "/editor")`, `url("mara")`. Same file: `expectNoHorizontalScroll(page)`, `expectTapTargets(page)`.
- **Sign-in** (no inbox, no password): `signInAs(context, email, { handle, plan })` in `tests/e2e/fixtures/auth.ts` creates the user, optionally sets `paid_plan` and a published page copied from `mara`, then opens a secret-key magic link through the real `/auth/callback`. Usual wrappers in `tests/e2e/fixtures/data.ts`: `signedInUser(context, { plan })` (fresh user + published page), `makeUser`, `insertPage`, `setPlan`, `setPublished`, `cleanupUsers()` in `afterAll`. A draft of your choosing: `userWithDraft(context, label, draft)` in `tests/e2e/m2/blocks-helpers.ts`.
- **Seed users** (`supabase/seed.sql`): `mara@example.test` (handle `mara`, published, every block type) and `nico@example.test` (Studio, handle `nico-demo`, two stuck domains). `signInAs(context, "mara@example.test")` signs the seed user in (`tests/e2e/m1/auth-smoke.spec.ts`).
- **Admin**: `signInAsAdmin(context)` in `tests/e2e/m5/admin-helpers.ts` (a throwaway user with the local-only admin claim of `src/lib/admin/principal.ts`; `ADMIN_USER_IDS` cannot change per run).
- **Email**: Mailpit at `http://127.0.0.1:54324`; `signInLinkFor(address)` and `waitForMessages` in `tests/e2e/fixtures/mailpit.ts`.
- **Stubs**: Stripe (`tests/e2e/fixtures/stripe-stub.ts`: `ensureStripeStub`, `deliver`, `postWebhook`), Vercel domains API (`tests/e2e/fixtures/vercel-stub.ts`: `markDnsReady`, `setDomainState`), Google sign-in (`tests/e2e/fixtures/google-stub.ts`), OAuth and MCP clients (`tests/e2e/fixtures/oauth.ts`, `tests/e2e/fixtures/mcp-client.ts`). Raw requests with an explicit Host header: `rawRequest` in `tests/e2e/fixtures/http.ts`.
- **Shared editor locators** (`tests/e2e/m7/toolbar-helpers.ts`, `tests/e2e/m2/editor-helpers.ts`): `getByTestId("workspace-toolbar")`, `getByRole("tablist", { name: "Workspace" })` with tabs `Edit`, `Design`, `Share`, `locator("[data-save-status]")`, `locator("[data-publish-status]")`, `getByTestId("preview-screen")` inside `getByTestId("preview-bezel")` (desktop) or `getByTestId("mini-phone")` (phone), app nav `getByRole("navigation", { name: "App sections" })`. The editor is ready when `getByLabel("Display name", { exact: true })` is visible.
- **Rendered page hooks** (preview and live): `locator("[data-page-root]")`, `[data-block-id="<id>"]`, `[data-block-type=link]`, `[data-item-id="<id>"]`, classes `.pg-name`, `.pg-bio`, `.pg-link`.

## Keeping this map true

A unit test checks that every repo path cited in this file exists, so a rename or delete fails `pnpm verify` until the row is fixed.
A change to a feature (route, selector, main module, covering spec) updates its row in the same commit.
A new surface gets a new row in the same commit as its first spec.
Quote selectors from `tests/e2e/` or the component source; never from memory.
Keep it under 300 lines: one row per surface, details stay in the specs.
