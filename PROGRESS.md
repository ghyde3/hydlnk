- **Known issues (security review mediums and lows, reviewer notes; none critical):**
  1. Same-second event order can flip a paying account to Free: the stale check in `apply_subscription_state` is `<`, so an `incomplete` event with the same `created` second applied after `active` clears the plan until the next event. M4-04 step 4 requires `incomplete` to mean Free, so the fix has to be a tie rule (for example never let `incomplete` overwrite a paid state of the same subscription id), not a change of mapping.
  2. A second Checkout during webhook lag (up to about 30 s after paying, the plan is still `free`) creates a second subscription. Fix: list the customer's live subscriptions in `startCheckout` and answer 409 (the code exists in `portal.ts`).

  4. `STRIPE_API_HOST` and `VERCEL_API_BASE_URL` are refused only when `VERCEL_ENV=production` (M4-01 step 4); a stray one on a preview deployment would send the token to that host.
